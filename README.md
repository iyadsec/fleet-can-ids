# FLEET-GUARD

**Fleet-Level Graph-Based Anomaly Reasoning for Coordinated CAN Attack Detection**

Research code and archived results for FLEET-GUARD (VehicleSec 2027 submission).
**Repository:** [github.com/iyadsec/fleet-can-ids](https://github.com/iyadsec/fleet-can-ids)

Provenance of every archived number, and corrections to earlier documentation:
[docs/RESULTS_PROVENANCE_AND_CORRECTIONS.md](docs/RESULTS_PROVENANCE_AND_CORRECTIONS.md).

## 1. Architecture and contribution

FLEET-GUARD correlates local CAN anomaly evidence across vehicles. Each vehicle scores windows with a
benign-trained Isolation Forest and emits a compact behavioural descriptor. The fleet stage links similar
descriptors in a constrained cosine kNN graph, embeds them with self-supervised GraphSAGE, clusters the
embeddings with DBSCAN, and accepts a cluster as a coordinated campaign only if it spans several vehicles
and is cohesive. The contribution is the fleet-level reasoning that separates isolated or unrelated
incidents from multi-vehicle campaigns.

| Stage | As executed in the June 2026 run |
|-------|----------------------------------|
| Windows | 100 frames, stride 50 |
| Local IDS | Isolation Forest per platform, 200 trees, seed 42, benign training only; θ_weak 0.45, θ_strong 0.70 (Hyundai/Kia) / 0.85 (Chevrolet) |
| Descriptor | 24-D behavioural vector per window (local); graph view 9-D, z-scored with the global benign-train fleet scaler; cohesion view up to 8 behaviour features, minus any with between-/within-vehicle variance ratio > 5 in the scenario (6–8 used) |
| Graph | Cosine constrained kNN, τ = 0.95, k_same = 2, k_cross = 5 |
| GraphSAGE | 9→64→32, 30 epochs, Adam lr 0.01, weight decay 5e-4; link loss + 0.25 × MSE to normalised anomaly score; no labels |
| Clustering | DBSCAN on standardised PCA-8 embeddings, eps 0.5, min_samples 2; fragment consolidation 0.85 |
| Decision | ≥ 2 distinct vehicles, cross-vehicle support ≥ 1, cohesion ≥ 0.5, cluster size ≥ 10 |

The fleet parameters were selected on a separate validation suite, not the test scenarios.

## 2. June 2026 setup and results (primary baseline)

Dataset: OCSLab Car-Hacking / DataChallenge 2019 (Chevrolet, Hyundai, Kia), platform-balanced split with
temporally separated segments and 100-frame guard bands. 90 runs = 9 conditions × 10 seeds. Archived
tables: `experimental-2026-06-23/01_primary_ocslab_balanced/tables/` (P4–P12). They were generated by
commit `61a8203` on branch [`cursor/campaign-clustering`](https://github.com/iyadsec/fleet-can-ids/tree/cursor/campaign-clustering).

| Strong: campaign F1 | 0.533 | 0.733 | 1.000 |
| Strong: membership F1 | 0.490 | 0.725 | 0.928 |
| Weak: campaign F1 | 0.067 | 0.500 | 0.717 |
| Weak: membership F1 | 0.057 | 0.564 | 0.825 |

Non-campaign scenarios (P6): S0 benign fleet and S1 isolated attack, false-campaign rate 0.0. S0 contains
one participant, so the ≥ 2-vehicle rule cannot fire. It tests suppression of local alerts, raised on
54.3% of its benign windows. S2 (unrelated incidents): incorrect merging **0.400**. All five incidents are
fuzzy attacks, and all four merges came from the same Kia fuzzy recording. Under a consistent definition
the S2 false-campaign rate is also 0.400. Replay has no test windows and was not evaluated. In every fleet
scenario 100% of windows were forwarded to the fleet stage.

## 3. Controlled campaign generation

Public CAN datasets contain no naturally recorded coordinated fleet attacks. S3/S4 assemble labelled OCSLab
windows from several logical vehicles. Each participant contributes 5 attack and 5 benign windows. Before
graph construction, a shared malfunction-derived prototype is blended into all 10 descriptors of each
attacked participant at strength 1.0, benign windows included. The prototype is the clipped mean of all
malfunction descriptors across all splits. Anomaly scores are not recomputed. Cosine similarity, GraphSAGE,
DBSCAN and the decision then run unchanged and without labels. S3/S4 therefore evaluate detection of
descriptor-coordinated campaigns under controlled similarity.

## 4. Graph, GraphSAGE, DBSCAN and decision

Nodes are forwarded descriptors. Each node links to up to 2 same-vehicle and 5 cross-vehicle neighbours with
cosine similarity ≥ 0.95 on the 9-D scaled view. GraphSAGE is trained per scenario without labels. DBSCAN
groups the PCA-8 embeddings, and fragments with centroid similarity ≥ 0.85 are merged. A cluster becomes a
campaign alert if it covers ≥ 2 vehicle tokens with cross-vehicle support, reaches cohesion ≥ 0.5 in the
behaviour view and has ≥ 10 nodes. Labels are used only for scenario assembly and scoring.

## 5. Reproduction and dependencies

Python 3.10+ for this repository (`pip install -r requirements.txt`, `python scripts/check_environment.py`).
Raw datasets are not included; see [docs/datasets.md](docs/datasets.md) and set `OCSLAB_DATASET_DIR` /
`CTT_DATASET_ROOT`.

Verify the archived June tables without rerunning:

```bash
python scripts/verify_balanced_campaign_tables.py
python -m pytest tests/ -q
```

The June tables were produced by `scripts/run_balanced_publication_run.py` on branch
`cursor/campaign-clustering`. That runner imports modules that were never committed. They are published,
verified against the June bytecode, in [`reproducibility/june_2026/`](reproducibility/june_2026/), together
with the June environment, hashes and a script that reruns the June experiment from raw data. A rerun
performed this way reproduced every June detection result exactly. The numbered reference pipeline in
this branch (`experiments/01`–`09`,
`configs/default.yaml`, `python experiments/run_full_pipeline.py --config configs/default.yaml`)
implements the same stages but did not produce Tables P4–P12.

Paper-to-file mapping: [docs/paper_pipeline.md](docs/paper_pipeline.md).

## 6. Descriptor size (Table P5)

The archived 53.69% bandwidth reduction (`table_P5`) compares a nominal 1,600 B raw window with the
in-memory size of a descriptor row (741 B). That size includes the absolute path of the source recording,
so it depends on the directory layout of the machine that ran the experiment. The figure is not a
measurement of transmitted descriptor size and is superseded. It is not a fleet bandwidth figure either,
because all windows were forwarded and consecutive windows overlap by 50 frames. Descriptors reduce raw CAN
exposure but give no formal privacy guarantee.

## 7. Limitations

- S3/S4 similarity is controlled: the prototype is computed across all splits and is also applied to the
  attacked participants' benign windows. June campaign results measure detection of descriptor-coordinated
  campaigns under this construction, not of naturally recorded coordinated attacks.
- Fleets are logical vehicles assembled from three OCSLab platforms, not concurrently recorded vehicles.
- Windows overlap (stride 50). The vehicle-level pooled table in `results/` (PR-AUC 0.9273) used a random
  stratified 70/15/15 split of overlapping windows, so adjacent train/test windows share frames. Treat it
  as optimistic.
- The manuscript's historical edge-connectivity table and the M1–M3 ablation come from earlier
  configurations, not the balanced run. The balanced run's sweep is `table_P10`.
- Cross-dataset (can-train-and-test) fleet results use ground-truth-assisted scoring: cluster selection
  uses labels, and the "consistency rule" uses the scenario name. They are not deployable detection.
- Replay was not evaluated at fleet level; no local filtering occurred (100% forwarded).
- No claim of production readiness or real-time operation.
