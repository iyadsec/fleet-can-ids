# Fleet-Aware CAN-Bus Intrusion Detection

Research codebase for **Fleet-Aware Intrusion Detection for Coordinated CAN Attack Campaigns in Connected Vehicles**.

The IEEE Experimental Evaluation tests four hypotheses (**H1–H4**) under a deployment-realistic pipeline: local self-supervised detection → compact behavioural descriptors → fleet graph correlation → final **isolated vs coordinated** attack decisions.

---

## Architecture (final evaluation pipeline)

```
Vehicle CAN traffic
  → Vehicle-Level IDS (Isolation Forest, self-supervised)
  → Anomaly Descriptors (behaviour-only uplink; no raw payloads)
  → Behaviour-Normalized Fleet Graph (cosine kNN, cross-vehicle edges)
  → GraphSAGE Fleet Correlation (structure-only training — no attack labels)
  → DBSCAN on GNN embeddings
  → Final decision: isolated_attack | coordinated_attack
```

**Runtime fleet decisions** use **behavioural cluster cohesion** and **multi-vehicle graph structure**. Attack-type names (`flooding`, `fuzzy`, `replay`, `malfunction`) appear **only** in evaluation tables and visualisation (e.g. Figure 6, Table 5), not in GNN inputs or coordinated-attack gating.

## Hypotheses (H1–H4)

| ID | Claim | Primary evidence |
|----|-------|------------------|
| **H1** | A lightweight self-supervised vehicle IDS detects suspicious CAN windows well enough to feed the fleet layer | Table 1, Figure 2 |
| **H2** | Descriptor uplink is **smaller** and **safer** than raw CAN while preserving anomaly evidence | Table 2, Figures 4–5 |
| **H3** | Behavioural descriptors **generalise across vehicle platforms** without raw CAN transfer | Table 3, Figure 6 |
| **H4** | GraphSAGE fleet correlation classifies **coordinated campaigns** beyond isolated local alerts | Tables 4–5, Figures 7–8 |

Interpretation text: `paper/results/ieee_experimental_evaluation_interpretations.md`  
Export index: `paper/IEEE_EXPERIMENTAL_EVALUATION_INDEX.md`

### Headline results (current bundle)

**H1 — Vehicle IDS (Table 1; Figure 2)**  
PR-AUC **0.927**, ROC-AUC **0.786**, precision **97.3%**, recall **46.0%**, F1 **62.4%**, FPR **3.95%** (FPR ≤ 5% threshold).

**H2 — Descriptors (Table 2; Figures 4–5)**  
**12.6×** compression (~2,076 → ~165 bytes/window), **92%** per-window bandwidth reduction, **94%** fleet reduction @ 100 vehicles (~7.6 GB → ~425 MB). Figure 5 shows payload bytes and CAN IDs are **not transmitted** on the descriptor uplink; anomaly evidence is **preserved**. Limitation: vehicle fingerprinting from descriptors remains ~**99.97%** (Table 2).

**H3 — Cross-vehicle (Table 3; Figure 6)**  
Mean leave-one-vehicle-out ROC-AUC **0.745**, mean F1 **0.896**, vehicle-agnostic score **0.821** (`paper/results/table_03_vehicle_agnostic_score.csv`).

**H4 — GNN fleet (Tables 4–5; Figures 7–8)**  
Campaign recall **100% (4/4)** vs **0%** local-only; campaign precision **80%**, cohesion **0.984**; **7,267** `coordinated_attack`, **49,760** `isolated_attack` events (`paper/results/table_final_attack_decision_summary.csv`).

## Reproduce the IEEE paper bundle

### Requirements

- **Python**: 3.11 or 3.12 recommended (3.13+ may need a recent PyTorch / PyG build for GNN training)
- macOS / Linux / Windows

### 1) Clone and install

```bash
git clone https://github.com/iyadsec/fleet-can-ids.git
cd fleet-can-ids

python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Sanity check:

```bash
python3 -c "import numpy,pandas,sklearn,matplotlib,networkx,torch; print('deps ok')"
```

PyTorch Geometric is required for **`run_final_gnn_fleet_decision_evaluation.py`** (H4). H1–H3 scripts do not need PyG.

### 2) Point the config to your local dataset

Edit `configs/fleet_ids.yaml`:

```yaml
data:
  external_dataset_dir: "/absolute/path/to/your/Dataset"
```

Use an **absolute path**. Do not commit datasets to GitHub.

### 3) Ensure processed inputs exist

Minimum artefacts under `data/processed/`:

- `window_features.csv`
- `anomaly_descriptors.csv`
- `anomaly_descriptors_transmit.csv`
- `vehicle_anomaly_predictions.csv`

If missing:

```bash
python3 run_all_experiments.py --config configs/fleet_ids.yaml --skip-existing
```

Or run stages `experiments/01_load_dataset.py` … `experiments/05_generate_descriptors.py`.

### 4) Run evaluations (H1–H4) and export

```bash
python3 run_vehicle_level_evaluation.py --config configs/fleet_ids.yaml
python3 run_descriptor_security_experiment.py --config configs/fleet_ids.yaml
python3 run_cross_vehicle_generalisation.py --config configs/fleet_ids.yaml
python3 run_final_gnn_fleet_decision_evaluation.py --config configs/fleet_ids.yaml
python3 run_ieee_paper_exports.py
```

`run_ieee_paper_exports.py` automatically re-runs missing prerequisite experiments when required CSVs or figures are absent.

### 5) Verify outputs

```bash
ls paper/tables/*.tex paper/figures/*.pdf paper/results/*.csv
cat paper/IEEE_EXPERIMENTAL_EVALUATION_INDEX.md
```

## Troubleshooting

| Issue | Fix |
|-------|-----|
| `python: command not found` | Use `python3` or activate `.venv` |
| Missing packages | `pip install -r requirements.txt` |
| Dataset not found | Set absolute `external_dataset_dir` in `configs/fleet_ids.yaml` |
| PyG / torch errors on H4 | Install matching `torch` and `torch-geometric` wheels |
| Slow GNN run | Set `retrain_gnn: false` after first successful train |
| Stale paper figures | Re-run `run_descriptor_security_experiment.py` and `run_ieee_paper_exports.py` |
| OneDrive / sync hangs on savefig | Regenerate figures locally; close PDF viewers locking files |
