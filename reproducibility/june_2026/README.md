# June 2026 reproducibility snapshot

This directory makes the June 2026 balanced OCSLab run (batch `20260614T201936`, Tables P4–P12) reproducible
from a public commit. The runner of that batch, `scripts/run_balanced_publication_run.py` at commit
[`61a8203`](https://github.com/iyadsec/fleet-can-ids/tree/61a82038ffcac2066d57d524f9305be88dabe212)
(branch `cursor/campaign-clustering`), imports modules that were never committed. Those modules are
published here, together with the evidence that identifies them as the June versions. Nothing in this
directory replaces or edits an archived result; `experimental-2026-06-23/` and the commit `61a8203` outputs
are unchanged.

## Module verification

Python writes a `.pyc` file the first time it imports a module. It records the size and modification time of
the source and contains the compiled code object. The June batch started at 2026-06-14 20:19:36 UTC; the
bytecode for these modules was compiled on 13–14 June before that time, and the balanced runner's own
`.pyc` shows that the batch ran with bytecode writing enabled. A snapshot module is **verified** when its
size equals the size recorded in a June `.pyc` whose source is dated before the batch, and compiling the
snapshot source gives a code object equal to the one in that `.pyc`. Code-object equality covers
instructions, constants and docstrings, names, nested functions and line numbers. It does not cover
comments or whitespace that leave line numbers unchanged. Comparing raw marshal bytes is not used, because
CPython's marshal output depends on reference counts. A changed constant, an inserted line and an appended
comment (which changes the source size) were all detected in negative controls.

The original `.pyc` files embed the absolute path of the June working tree, including the author's account
name, so they are not published. They are kept privately, unmodified, with their SHA-256 listed in
`bytecode_record.csv`. For each module the record stores a digest of the June code object computed over
every field that code-object equality compares except the file name, so no path is needed. Constants are
canonicalised, so the digest does not depend on the hash seed. `verify_snapshot.py` compiles each snapshot
source with Python 3.13, computes the same digest and compares it with the record. When the record was made,
digest agreement was checked against direct code-object equality for all 42 modules, and the regenerated
`MANIFEST.csv` was byte-identical to the one produced from the `.pyc` files. The public check therefore
relies on the record. Anyone holding the original files can check them with
`verify_snapshot.py --bytecode-dir DIR`, which confirms each SHA-256, the header fields and the digest. No
bytecode in this repository has been regenerated or presented as June evidence.

| Status | Modules | Needed by the runner |

| **UNVERIFIED**: matches only bytecode recompiled after the batch (source dated 2026-06-16) | `final_shared_configuration/__init__.py` (empty), `final_shared_configuration/shared_config.py` | yes |
| **UNVERIFIED**: source differs from the June bytecode | `coordinated_campaign_refinement/eligibility_audit.py`, `coordinated_campaign_refinement/tables.py` | no |

The four unverified modules must not be presented as the June versions. The June bytecode of
`shared_config.py` was overwritten when it was recompiled on 16 June, so no record of its June content
remains. The reproduction below regenerates the June shared configuration
(`configs/final_shared_fleet_configuration.yaml`) and all 90 June runs with it, so its behaviour on this path
matches June. That is behavioural evidence and does not prove the source is identical.

Run `python verify_snapshot.py` with Python 3.13 to regenerate `MANIFEST.csv`. Module verification is
separate from experiment reproduction: `reproduce.py` and `compare_with_june.py` do not use the bytecode or
the record.

Of the 29 modules the runner needs, 25 belong to the three packages named in the provenance document
(`final_end_to_end_publication_run`, `coordinated_campaign_refinement`, `final_shared_configuration`) and
4 are not in those packages: `shared_statistics.py` and `strong_campaign_extended/{__init__,guard,metrics}.py`.
The remaining 13 snapshot modules are in those packages but are not imported by the runner.

## Reproducing the June run

```bash
git clone https://github.com/iyadsec/fleet-can-ids.git
cd fleet-can-ids && git checkout docs/vehiclesec-2027-provenance   # this snapshot
mkdir ../june_tree && git archive 61a82038ffcac2066d57d524f9305be88dabe212 | tar -x -C ../june_tree
python3.13 -m venv ../venv && ../venv/bin/pip install -r reproducibility/june_2026/requirements_june_2026.txt
../venv/bin/python reproducibility/june_2026/reproduce.py --tree ../june_tree \
    --dataset-dir /path/containing/OCSLab_folder
../venv/bin/python reproducibility/june_2026/compare_with_june.py --tree ../june_tree \
    --path-map "/resolved/path/containing/OCSLab_folder=<June dataset prefix>" --out check
```

`--dataset-dir` is the directory that contains `In-Vehicle Network Intrusion Detection Challenge/`.
`reproduce.py` copies `src/` into the tree, refusing to replace a file that differs, and moves the committed
June outputs to `_june_reference/` for comparison. It then rebuilds windows and features from the raw data,
installs the archived June split and runs the balanced runner (local IDS, descriptors, shared-configuration
search, 90 runs, edge sweep, tables). A full run takes about 15 minutes on an Apple-silicon laptop. The June
dataset prefix is `dataset.external_dataset_dir` in `_june_reference/.../configs/balanced_master_experiment.yaml`.
Without `--june-root`, outputs that were never committed are checked against `june_local_artifact_hashes.csv`.
These hashes include the June absolute path, so with a different dataset location only the path-independent
artefacts (the three Isolation Forest models and `validation_scenario_manifest.csv`) can match them.

### The split must be taken from the archive

`scripts/build_balanced_split.py` seeds the trace assignment with `seed + hash(vehicle_model) % 997`
(`src/experiments/final_end_to_end_publication_run_balanced/balanced_split.py`, lines 183 and 192). Python
randomises string hashes per process, so rerunning the script gives a different split each time. The default
`archived_split` stage therefore installs the committed June split manifests. `split_hash_diagnostic.py`
tried all 997 offsets per platform: 30 offsets regenerate the June Hyundai split and 28 the Kia split, and
the Chevrolet split does not depend on the offset. The archived split is therefore one that the committed
code can produce (`reproduction_check/split_hash_offsets.csv`). A rerun with a regenerated split
(`--stages overlay preprocess split run`) completed 60 of 90 runs: all 30 weak-campaign runs failed because
the regenerated split left no eligible weak Kia instances (`reproduction_check/regenerated_split_run/`).

### Raw-data integrity

The reproduction must use complete raw files. In the local June dataset folder two Kia files are now 0 bytes
(`car_track_final_2nd_train/Malfunction_2nd_KIA_Soul_train.csv` and
`car_track_preliminary_train/Malfunction_KIA_Soul_train.csv`). The loader skips them, and the reproduction
then diverges. Three independent intact copies agree with each other:

| File | Bytes | SHA-256 |
|------|-------|---------|
| `Malfunction_2nd_KIA_Soul_train.csv` | 20,637,729 | prefix `1aa88fbbd96dae91` |
| `Malfunction_KIA_Soul_train.csv` | 5,809,730 | prefix `126ba8c503bcc9be` |

With the intact copies, the rebuilt clean data, window features and window manifest equal the June files
once the dataset path is restored. This shows that the June run read complete files.

## Reproduction check (2026-11-23)

Performed on a clean `git archive` of `61a8203` with this snapshot, the June environment, the default stages
and a copy of the OCSLab data at a different path (`reproduction_check/artifact_comparison.csv`, 162
artefacts; `difference_explanations.csv`). Uncommitted outputs were compared with the local June copies,
whose SHA-256 equal `june_local_artifact_hashes.csv`.

| Result | Artefacts |
|--------|-----------|
| Identical, or identical after restoring the June dataset path | 78 |
| Equal values (master configuration; YAML line folding of the longer June path only) | 1 |
| Equal in every cell except wall-clock, memory and run-identifier columns | 20 |
| Different, explained below | 63 |
| Missing | 0 |

- **Detection results are reproduced exactly.** All 90 runs complete. `run_level_metrics.csv`, campaign,
  membership, candidate, fragmentation, safety and local metrics, Tables P4 and P6–P11, the vehicle-level
  results, the validation-suite parameter search and the selected shared configuration all equal June. The
  three Isolation Forest models are byte-identical. P6 matches the committed local `table_P6` (S2 incorrect
  merging 0.0); the bundle's 0.400 comes from the per-run metrics, as described in the provenance document.
- **`scaler_id` (57 artefacts)** is a random `uuid4` label created on each run; the scaler values are identical.
- **Descriptor size (P5 and 3 descriptor-analysis files)**: the descriptor byte count is the in-memory size of a
  descriptor row, which includes the absolute `source_file` path. It is 678 B here and 741 B in June; the
  difference is the 63-character difference in path length. The archived 741 B and 53.69% figures therefore
  depend on the June directory layout, which is a further reason they are marked superseded.
- **Statistical tests (P12 and `primary_statistical_tests.csv`)**: for campaign F1, membership precision and
  membership recall, the mean difference, raw p-value, effect size and significance flag equal June. Only
  the latency rows differ, because latency is measured in wall-clock time. The Holm-adjusted p-values shift
  because the same correction family includes the latency tests. The same single comparison is
  Holm-significant in both runs.

## Excluded

No credentials, private data, logs, caches, bytecode or code written after the June run. Raw OCSLab data and large intermediates (features, descriptors, models) are identified by hash
in `june_local_artifact_hashes.csv` and are not redistributed.
